# Selecting verification

From the repository root, follow [Setup and feedback](../CONTRIBUTING.md#setup-and-feedback) before running these checks. Choose the smallest group that reaches the changed boundary. Each command has its own scope and prerequisites. The changed-path runner combines individual feedback budgets with the shared suite budget. The integrated and complete local integration routes use their own suite budgets.

## Shared fixture inputs

For a lane that requires an existing Docker runtime, use its declared executable, local context and immutable image. The standard inputs are `GITJIG_DOCKER_BINARY`, `GITJIG_DOCKER_CONTEXT` and `GITJIG_RUNTIME_IMAGE=sha256:...`. Supply the absolute private `GITJIG_DOCKER_CONFIG_DIRECTORY` when the lane requires it. Use an existing canonical, owner-private directory already shared with the engine for `GITJIG_RUNTIME_FIXTURE_ROOT`. Keep the root outside the repository and registered projects. The fixtures use that configured route and leave image, context and host mounts under the owner's control.

Native Git lanes require a trusted Git executable and owned temporary repositories. Terminal lanes specify where Python 3 and a PTY are needed. Installed lanes distinguish an explicitly prepared offline npm cache from a frozen bundle receipt. Use the specific inputs named in the chosen entry.

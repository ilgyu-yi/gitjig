# Provider maintenance

Audience: contributors changing gitjig's provider integration. Application users should read [Accounts and providers](../docs/providers.md).

## Governed role execution bounds

`src/workflow/execution-bounds.ts` owns the shared five-minute role-body default and sixteen-request allowance. Normal governed roles and publication judgments record the same captured bounds before admission/dispatch and pass them to the role runner. The adapter retains explicit caller timeouts from 1 through 600,000 milliseconds; a default change never extends an existing invocation or rewrites historical bounds, failed output or consumed usage.

The wall timer starts before Pi session preparation and clears before the final owned-close/checkpoint/release tail. It is not a five-minute total cleanup guarantee. Existing cancellation, ownership and bounded cleanup remain necessary; neither ongoing output nor pings renews the deadline. A timeout retains incomplete original output without making it a usable verdict or automatically retrying. The default accommodates longer valid role output; it does not promise a provider latency or eliminate service/stream failures.

## Ownership and extension boundary

Pi owns catalogues, authentication resolution, token refresh and wire protocols. Gitjig owns admitted execution, original task tails, cancellation, idle proof and cleanup. Direct providers share one owned chat runtime. Claude Code-backed execution also needs a native process adapter. A trusted programmatic runtime is borrowed: its caller owns authentication and lifetime, so it cannot supply gitjig-owned idle proof.

Extend compatible direct providers with capability data and proportionate conformance checks. Do not copy the controller/runtime owner for each model or provider. A catalogue entry is not execution qualification. Keep application-managed and deliberately selected external credential modes distinct.

Claude builtin compatibility uses the selected native executable and canonical SDK origin metadata, not a catalogue of policy names. Native registry origin does not prove purpose or harmlessness; exact tools, MCP provenance, permission denials and controller standing remain the effect boundary. Keep SDK user/project settings isolation and sync controls explicit. Do not add account-specific plugin names to programmatic settings. Native executable pins prevent mid-run identity drift; they are not per-account compatibility branches. Marketplace identity alone does not establish an external managed issuer. The SDK [settings-source contract](https://code.claude.com/docs/en/agent-sdk/claude-code-features) explains which managed/global inputs remain outside that isolation control.

## Application model and credential binding

Model management, conversation UI and role selection share the application resolver. It creates an original owned Pi runtime for one admitted source/model, uses original codecs and closes it at settlement while retaining history. Config integrity hashes stay in private admission state; model/run evidence excludes credentials and those hashes. Per-provider account epochs invalidate old admitted sources before original account writes. Operator setup and the explicitly selected external-profile route are documented in [Accounts and providers](../docs/providers.md).

Configuration identity excludes credential values and key hashes. Run/launch identity remains distinct from stable configuration identity. For stored profiles, the public header transform preserves original authentication headers: caller additions must match the resolved subset, and an unknown added header or destructive callback refuses before transport.

Guided Claude connection is a Claude-specific application setup helper, not a provider registry or a second runtime owner. It receives the operator environment captured at CLI entry, discovers metadata without execution and uses the existing bounded native observation helper for explicit login checks. ApplicationStartup owns its serialization, cancellation/close and exact-byte save boundary. Opaque reviewed candidates bind the selected executable, login route, account organization and concrete app-owned prerequisite target; they do not authorize model dispatch or implicit model changes. Native account-status commands may refresh their selected native store. Credentials remain native-owned. Saved bridge changes still activate through normal relaunch; external advanced profiles remain supported separately.

## SDK compatibility surface

The finite compatibility names in `src/pi/sdk-metadata.ts` come from the MIT-licensed Pi coding-agent 1.3.0 `dist/core/provider-attribution.js`; the installed package.json declares MIT; this package does not ship a LICENSE file. Only seven metadata names are admitted, without copying SDK provider routing or header values. Original auth-header values remain protected. On upgrade compare this surface and run the managed original-codec consumer; new names fail visibly until reviewed. Managed sessions disable Pi install telemetry through the public SettingsManager preference. The CLI ignores PI_TELEMETRY once at startup, before sessions exist, because the original SDK gives it precedence over preferences. An embedding host must make its own explicit startup choice. Original provider session headers remain delegated to Pi.

The copied metadata names and their upstream source attribution are also recorded in the distributed [third-party notices](../THIRD_PARTY_NOTICES.md). Keep the attribution when moving or replacing this compatibility surface.

Integer operands that bind freshness, original recovery and exact target identity use public opaque integer schemas. Keep the native JSON schema unchanged while refusing lossy fractional conversion through Pi; exercise actual mutation boundaries as well as schema validation when upgrading the SDK. Existing canonical conversion of whole-number strings and booleans is separate from fractional truncation.

## Bounded conversation results

The Pi coordination tool preserves the scoped controller result read. Every summary or page calls that read again with only the result ID before formatting; a fingerprint is consistency evidence, never read authority. Results up to 8 KiB retain their existing JSON representation. Larger results, within the controller’s 128 KiB ceiling, return an explicitly marked summary with identity, outcome metadata, complete blocker entries that fit and omission counts. The summary never turns omitted evidence into success.

Detailed inspection uses the same `conversation_result` tool with its returned SHA-256 fingerprint and UTF-8 byte cursor. Each serialized content text, including JSON escaping and page metadata, stays within 8 KiB; the transport envelope adds its own overhead. Pages reconstruct the exact serialized result; changed content, invalid cursors and lost audience scope refuse. This also keeps ordinary failure and cleanup metadata visible when a large report cannot fit inline. Only the independent governed producer can supply missing source-fit judgments; the coordinator’s result inspection cannot adopt them.

New governed assignments publish `governed-work-observation/v1`: a compact immutable observation with selected identities, usage, blocker/action omissions and an exact `detailRef`. The rich original observation is retained as a closed-purpose JSON artifact, limited to 16 MiB with a five-second observed IO budget; every owned operation is joined before timeout is reported. Read its advertised `detailRead` operands with the same result ID. Each detail page repeats the original audience/root/project checks, validates the original artifact digest/length and returns at most 8 KiB. Later work or journal changes do not regenerate that snapshot. Missing, altered or unsafe artifacts refuse; a hash never grants access. This adds no general host-file read, provider/bridge permission or model execution.

Legacy publications keep their original bytes and paging. This stage does not relax C5's 64 KiB metadata bound or add large legacy cancelled-assignment recovery. Human `/result` and `/work` continue to inspect the selected current work; they are distinct from the immutable historical snapshot exposed by the native result reader.

Verify the pure formatter, scoped controller/Pi consumer and original public SDK/MCP gate separately. A scripted native transport proves message handling and permission coherence, not actual native spill thresholds or live model comprehension.

## Maintained bridge choice

The derivative exposes provider configuration and typed lifecycle handlers for public SDK composition. Hosted declarations retain their own normalized model settings and use the captured native account for history reads, writes and removal. They require a synchronous host diagnostic sink; the host owns bounded persistence. Diagnostic failures occur before fresh native-query allocation, and synchronous slot replacement refuses the outer preparation without replacing the inner stream. Standalone configuration and welcome persistence remain part of the legacy initializer. Its debug and raw-record settings also remain standalone-only: hosted debug(), native CLI debug options and raw message recording stay closed even when those flags precede module import. A missing hosted diagnostic sink is an explicit pre-native refusal, and the sink retains its captured options receiver. The application consumes fresh declarations per prepared session and separate catalogue runtimes. Register and join the provider before exact-model lookup and AgentSession construction; do not inspect SDK pending queues or rely on session_start to select a missing model. The bridge and project-bash handlers use public Extension data without resource discovery. Reload recreates the declared runtime and invalidates prior contexts; failure and close also invalidate it. The latest diagnostic is a bounded atomic observation in agentDir/bridge-last-diagnostic.json, not an acceptance or recovery journal. The CLI preserves its invocation HOME, cwd and unrelated environment. The owned bridge receives an immutable explicit native environment, filtered to finite identity/presentation variables; SDK options replace the native subprocess environment. Parent environment changes cannot retarget the account or native executable. The launcher still owns TMPDIR for application artifacts. Both catalogue and session runtimes use explicit empty memory stores. The SDK still composes builtin catalogues and its availability refresh may inspect ambient credential existence (for example Vertex ADC through fs.access); that metadata is not bridge execution authority and no credential content is read by that check. Admission verifies the original registered bridge stream and exact selected model, while owned authentication/request guards refuse foreign dispatch. Do not require every ambient builtin to disappear from the SDK availability snapshot.

Project execution facts are provider independent. `ContainerScope` projects its admitted mount operands into a readonly description, separate from its host-side `workspaceRoot`. The role adapter and Pi session capture that value through their existing operation wrappers; session read-only admission can narrow project access. Public tool definitions describe actual shell/project coordinates, protected paths, disposable scratch and whether a readonly input mount was supplied. A mount is not a descriptor or verification result. Unknown operations retain generic relative-project guidance. Native connection cwd, sandbox permissions and the formatter contract remain separate.

The root-owned Claude response policy lives in `src/pi/claude-output-policy.ts`. Provider catalogue and actual selected runtime registration use the same bounded model projection. The final owned launch sets `CLAUDE_CODE_MAX_OUTPUT_TOKENS` from that owner's exact runtime limit; isolated summaries keep the same owner. This overrides only the response-policy field, not credentials, cwd, executable or argv. Native terminal `modelUsage` provides contradiction detection rather than permission to infer capacity from absent metrics. The [Native environment reference](https://code.claude.com/docs/en/env-vars) describes the setting for most requests; controlled propagation is not proof of every native exception. Qualify actual selected runtime behavior separately.

Governed role output schemas keep an object root with visible protocol properties. The selected Native tool-input path rejects top-level `oneOf`, `allOf` and `anyOf`; support for nested unions does not establish root-union compatibility. Supported planning adjudication uses the existing `if`/`then` vocabulary: require boolean `planAccepted`, require the constrained plan only on acceptance, and preserve the captured criteria-decision condition inside that accepting branch. A decline may omit its plan; a supplied plan still follows its original structural contract. This is one shared complete schema, not a relaxed Native projection. Strict host semantics and original-source checks remain separate. Schema maintenance must exercise acceptance, refusal, owner-decision exceptions and held-source/criteria identities through the SDK boundary; controlled transport does not qualify the actual provider.

Fresh adjudication's optional `decisionReferences.version1` binds the same detached known/synthetic identity sets to structural guidance and final strict decoding. Use compact enums and one item-level conditional, preserving the provider-compatible object root and both original context guards. A resolved host diagnosis cannot become an ordinary equivalence target; a model finding named `producer-integrity` remains ordinary. Historical inputs without this declaration keep their old schema/parser behavior. This does not replace original diagnostic receipt availability, semantic judgment or the Controller's complete chain/cycle/source checks. New findings remain independently accountable; a terminal projection alias requires its own original-source proof rather than equal text.

The current derivative adds fixed launch policy, scoped native ownership and cleanup, admitted tools, bounded summaries, typed terminal validation, text ownership and finite schema metadata. Fresh governed Claude roles additionally bind the public SDK JSON-schema channel to an original launch intent. Original SDK argument deltas, completed formatter/carrier/result and separate native-settlement evidence supply a typed persisted source; the strict role parser remains authoritative. Ordinary chat, isolated summaries and standalone initialization do not inherit that role-only formatter. Controller launch records retain the original dispatch intent/checkpoint independently from the final selected checkpoint. Malformed producer material remains a held evidence problem while original reservations and confirmed resources settle. Controller harvesting verifies selected-source provenance before excluding a transport representation. An exact compact text copy in the same terminal SDK result can alias the accepted strict value, while raw trace views, earlier attempts and already accounted claims remain retained. Selected invalid envelopes use literal supplemental accounting rather than losing nested findings to flat final collection; explicit recovery revalidates older extraction receipts. Complete strict role roots use their existing role/byte bounds, including distinct terminal text. Older keyed partial records retain exact source/location correspondence while only missing positions are supplemented. See its [current changes](../third_party/pi-claude-bridge/README.md) and [build instructions](../third_party/pi-claude-bridge/BUILD.md).

Assess an unchanged upstream bridge against these actual boundaries before adding or retaining a patch. A worker alternative must account for command/event/tool forwarding, live Pi session/UI coordination, callback reconciliation and process recovery. A launcher can constrain startup, but distinguishing a successful typed result from text and clean EOF requires a consumer that sees the result protocol. Count the full maintenance cost, not only visible patch lines.

The selected native account route uses one metadata assertion for setup and synchronous birth checks. Run it before the SDK host invokes its process-capable callback for every provider and summary. A sealed preflight refusal records no birth; attempted callback counts and all returned launch settlements still govern cleanup. Credential contents and inode identity are not frozen across native account refresh. The native callback retains the original metadata error. The existing compaction hook cancels failed summaries to prevent unsafe native fallback; Pi can report a generic compaction-cancelled error. Check the callback error, absent new birth and settled ownership rather than requiring that outer message to preserve the metadata reason.

Native tool request streaming is not permission evidence. Keep provider execution behind the exact captured SDK MCP invocation, including its tool-use identity, role name and arguments; native policy may refuse or rewrite a streamed request. Retain per-query pending admission across Pi stream resets and return approved serial results without waiting for later calls. Default SDK permission callbacks are finite role admissions, never persistent rules or general bypass. Permission-denied/terminal paths must demonstrate zero unapproved controller mutation through the original Pi plus SDK/MCP transport, including source/policy changes and owner closure. Native policy hooks retain their documented host-side limits.

Exact native INIT observation is the selected witness, not a requirement for every future adapter. The current derivative is a selected baseline, not a proven global minimum. On upgrades, inspect actual query births, tool/terminal/callback ownership and native cleanup with the selected SDK. Public upstream facilities are preferred when they are shipped and sufficient. Past controls cannot qualify a different version or live account.

# Conversation commands

`/inputs` shows sent requests that are still pending, including requests whose startup failed before model history was created. Review the original text and diagnostic, then explicitly retry or withdraw when the application establishes an undispatched request or a cleanly interrupted request that was requeued. Retrying an interrupted request can send the original text again with retained history; withdrawal does not undo prior activity. Retry preserves the original work and remaining allowance. Withdrawal keeps the text and attempts as retained evidence and starts no task. Native delivery uncertainty remains held for reconciliation. `/ready` directs pending requests here before recommending a new project task.

`/goal` creates, inspects and controls a persistent objective with bounded continuation and independent completion review. Use `/goal create`, then `/goal start`; navigation stays available during execution. See [Goals](goals.md) for pause, resume, criteria changes and separate work budgets.

`/resume` opens Gitjig's existing conversation navigator. Select a conversation or press Escape to cancel. `/resume CONVERSATION-ID` selects an exact accessible conversation. This switches the view; it does not retry pending work, restore an archived conversation or change its model. Cancellation keeps the command draft. A successful switch clears only that unchanged source command and preserves the destination draft. F2 uses the same navigator.

Ctrl+G then S selects a second conversation or closes the split. Side-by-side panes require at least 100 terminal columns. At a narrower width, the second conversation remains selected for the split; Ctrl+G then W switches the input pane. Widening the terminal restores both panes. Use your configured command key in place of Ctrl+G. The lifecycle menu (Ctrl+G then L) identifies archived conversations by name and full ID so you can restore the intended conversation even when names match.

`/name TEXT` saves an application display name. `/name` opens a text field; cancellation keeps the current name. `/name --reset` removes the explicit name and restores the derived label. Names contain 1..120 UTF-16 code units and no control characters. A governed conversation's actual role/purpose stays visible before its user label. Naming does not rename the native session file or change work, authority, history or pending obligations.

`/session` shows the current conversation's identity, display name, role, state, project, parent, native session identity and public model choice. Verified native history supplies message counts, recorded tokens and recorded cost, including after restart. Totals cover the whole native file, including abandoned branches, compaction/summary usage and copied fork context. They do not represent new conversation spend or billing. Missing or invalid usage is unavailable. Current context is unavailable without a live measurement; a live Pi session supplies its own context estimate. The command does not display credentials, private recipes or history paths. Escape closes it without clearing the command draft. The picker also shows bounded recent captured-input records and their separate handling/comparison states; see [Project file context](file-context.md).

`/fork` opens Pi's history tree. Use the arrow keys to select a context point, then press Enter to create and open a new conversation. Escape cancels and keeps the command draft. Browsing and selection leave the source history unchanged. The source must have verified native history. If its history or model changes while the selector is open, reopen the command.

`/clone` creates and opens a conversation with the current context and desired model choice. It also works for an empty conversation with no model selected. Each destination has its own draft and native identity. Forks and clones retain the original task references, shared allowances, delegation limits and pending governed obligations. Wait for active producers and cleanup to settle before copying their context. A successful command clears only its unchanged source command; newer and sibling drafts stay intact. If creation succeeds but opening fails, the diagnostic gives the new ID for `/resume`. Inspect that ID before manually repeating the creation command.

`/copy` copies the current branch's last assistant text, following Pi's text convention. It ignores thinking and tool arguments, trims surrounding whitespace and skips an empty aborted assistant message. If the latest remaining assistant message has no text, it reports unavailable rather than copying an older answer. Missing history, changed history scope, text over 1MiB or a failed clipboard write produces an error and keeps the command draft. This command uses the conversation where it was invoked, even if another view gains focus while history is read. Mouse selection copy remains separate.

These commands do not check out Git or create procedure standing. See [current capabilities and limits](capabilities.md). Generic positional prompts, stdin/print aliases, arbitrary plugins, prompt-template expansion and Pi RPC/JSONL compatibility are not provided; see [Usage](usage.md#noninteractive-input-limits).

Application conversations and assigned work use saved target model choices. A newly assigned child inherits the parent's desired choice; a target that already has a model keeps its own choice. Governed work captures that target choice as its baseline. Later default changes do not retarget that work or old execution records.

A waiting application conversation can resolve its saved model after restart. Automatic continuation requires complete dependency results and validated native history. Explicit resume can also account for unavailable dependency outcomes; an unavailable outcome is not success. Missing model, runtime, native history or cleanup leaves the waiting authorization available for repair. Work that used an explicit external profile requires its matching profile after restart. New owner input takes precedence over an older in-flight continuation.

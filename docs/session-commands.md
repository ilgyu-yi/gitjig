# Conversation commands

`/inputs` shows pending requests and their delivery status, including requests whose startup failed before model history was created. Select a request to read the original text, the recorded diagnostic and the available next step in your UI language. If an unstarted request needs its first model, choose one from the request review. Your draft and earlier request stay unsent. Open the request again to retry it. Retry or withdraw is available for an undispatched request or a cleanly interrupted request that was requeued. Retrying can send the original text again with retained history and uses the original work and remaining allowance. Withdrawal keeps the text, attempts and earlier activity on record. When earlier work blocks recovery, open it from the request. An unexpected exit can offer **Continue original request** for a first request proven to have stopped before model dispatch. This uses the original input, work and one remaining attempt, with the original model, runtime and project capture verified before dispatch. If that request’s execution allowance is exhausted, open **Review original execution allowance**. After confirming an extension, return to the original request and select **Continue original request** separately. Updating project protection leaves requests from the earlier policy held. The original request review identifies the policy update and opens the original work. Project continuation requires the same active runtime. If it differs, open runtime setup from the original request to apply the original settings. Continuing also checks the original model and account configuration before reserving a new attempt. Project continuation can be attempted once. If the project files differ from the original capture, the attempt stops before the model sees the request. Use **Review the original interrupted request** in readiness to see what changed and inspect the original work. Uncertain delivery or an interrupted successor stays pending for reconciliation. `/ready` directs pending requests here before recommending a new project task.

After gitjig accepts a send, the line above the editor shows a preview of what you sent while the request still awaits native delivery. The adjacent status describes the current preparation or response stage. Use `/inputs` to inspect the full original retained message. Once native history records the message, it appears in the transcript.

`/goal` creates, inspects and controls a persistent objective with bounded continuation and independent completion review. Use `/goal create`, then `/goal start`; navigation stays available during execution. See [Goals](goals.md) for pause, resume, criteria changes and separate work budgets.

`/resume` opens Gitjig's existing conversation navigator. Select a conversation or press Escape to cancel. `/resume CONVERSATION-ID` selects an exact accessible conversation. This switches the view; it does not retry pending work, restore an archived conversation or change its model. Cancellation keeps the command draft. A successful switch clears only that unchanged source command and preserves the destination draft. If the destination history is unavailable, the conversation opens with a diagnostic in its own pane. F2 uses the same navigator.

The parent conversation shows recorded blocked or unconfirmed governed results, including provider usage-limit rejections, and confirmed local model-request stops. When gitjig can identify one original stop, press **Ctrl+G then Enter** (or use your displayed keys) to open its recorded recovery review. Choose **Inspect original** or **Open result actions**, as displayed. If the shortcut says **Review delegated results**, use it to choose the assignment from the scoped list. The same list is available with `/result --delegated`. The list can also explain a stopped task that the parent was waiting on when its original result is unavailable. Where the original work can be verified, open it from that review. Opening either view keeps your draft and starts no work. The parent can also see a bounded set of typed descendant stops through verified original assignments in the same delegation. These include local request limits, recorded provider usage-limit stops, and governed blocked or unconfirmed outcomes. This summary can appear once the assigning runs have reached the recorded admission boundary.

For a nested stop, choose **Open result actions**, then **Open original coordinator** when available. This opens the conversation that assigned the stopped work and preserves both drafts. Use the displayed **Return to the originating conversation** shortcut to come back. The visit requires no model and leaves messages and work untouched. If gitjig cannot still verify the visit, use **Inspect original** to review the recorded work.

A blocked governed result shows current work guidance alongside the original outcome. When the original work can be assessed, its guidance can identify a missing account for the original role or an inactive execution runtime. Complete the named setup and return to the same parent conversation. For a provider usage limit, check the original account before resuming. The displayed reset is what the provider reported for that attempt.

When the result offers a setup action, use **Open result actions** to review the runtime from the same parent conversation. After applying settings or backing out, the original result shows the current prerequisite. If a conversation is holding account setup, the review identifies it and points to its open question, pending requests, readiness, or reclaim command when applicable. Choose **Open conversation blocking account setup** when offered. After addressing the hold, use the displayed return shortcut and reopen the same recovery review. Setup and resuming the original work require separate actions.

If the owner cancels work that a parent is waiting on, the parent can show the cancelled assignment before a result is available. Open its recovery entry to inspect the original work and check cleanup. This also works through verified intermediate waits. Any available restoration or continuation requires a separate action.

If a governed task fails to start before publishing a result, the originating parent can show the stopped assignment through verified intermediate waits. Gitjig shows unconfirmed cleanup first when it has a record of it. Use **Review delegated results**, select the assignment, then choose **Inspect original** to see the work and its available recovery options. The review works without a model response and keeps your draft in the parent.

If the parent says it cannot verify the current delegated wait, open **Review delegated results** to see results that gitjig can still verify. Choose **What to do when the wait cannot be verified** to find the parent conversation ID and recheck instructions. If the warning remains, keep the original task on hold and use that ID when asking for support. If gitjig can identify the assignment but cannot verify its original work, the assignment review also shows the original assignment ID for support.

A provider usage-limit review shows the affected role when recorded and the reset time the provider reported, or tells you that no usable reset time was supplied. This also works through verified intermediate waits. The same review shows any current shared work allowance hold. Check the original account's limits and use **Inspect original** to review a depleted allowance. Extending it requires confirmation and does not resume the task.

When an authorized parent continuation receives a failed delegated outcome, gitjig marks the handoff in the parent transcript. Use **Review delegated results** to inspect the original work. The event records what the parent received. Any eligible retry or recovery of the delegated work is a separate action.

If the parent could not start its continuation before queuing a result, choose **Review parent continuation** from the command menu. The review explains whether the original model profile is required and opens parent readiness or the existing delegated results. Return to the same conversation after checking its prerequisites. A previously queued result uses the separate `/inputs` delivery route.

If an intermediate delegated conversation could not start its continuation, choose **Review delegated continuation** in the original parent. Select the named conversation to see the cause, then choose **Open delegated conversation readiness**. After checking readiness, close it and use the displayed shortcut to return to the original parent. Both drafts are preserved.

You can ask the parent why an original delegated investigation stopped. Its status can identify the gitjig model request limit when the original evidence is complete, or explain that the result or failure cause could not be verified. Use **Review delegated results** to see the retained evidence. Continuing under the same instructions still requires the original assignment's eligible continuation.

If the task was delegated through another conversation, identify that coordinator in your question. The parent can explain the recorded failure and name the coordinator that assigned the original work. Check the original coordinator for current continuation eligibility, or use **Review delegated results** in the parent to inspect the work.

When an investigation is waiting for your response in a live dialog, a parent waiting on the investigation can show **Delegated input needed** with the keyboard shortcut. This works through verified waits for up to three ordinary investigation assignments in the same delegation. Choose **Open conversation with pending input** and select the investigation. Respond in the original dialog. When it closes, follow the displayed shortcut to return to the conversation you opened it from. Escape keeps that conversation open. If the input request expires or a wait in the chain is no longer current, the selection leaves you in the parent with a notice.

If gitjig restarts after an interruption while that input was pending, the same parent can show **Review interrupted input**. The review identifies the original task and whether cleanup was confirmed. Choose **Inspect original** to open that work’s recovery options without leaving the parent. The original input window closed during the interruption. Available actions depend on the original work’s recovery state.

When independent planning on a delegated change needs your decision, the parent can show **Delegated planning needs your decision**. Open the recovery entry to read the original questions. Choose **Open reply pane for planning questions** when available, send your answer, then choose **Keep feedback**. The answer is retained on the original work for review. Use the displayed return shortcut to go back to the conversation where you opened recovery. Resuming the work is a separate step.

In the conversation that directly delegated a blocked change, you can ask “Why did the original task stop?” or “Continue the original task under the same instructions.” The coordinator checks the current original assignment. A diagnosis leaves the child unchanged. Continuation requires an available route for that assignment. Complete any reported owner action and ask again from that conversation.

`/change replan WORK_ID` opens a review when retained evidence supports reconsidering failed checks or a failed file scope. Review the original request and the retained failure evidence in the original work conversation. Back is the default. If independent planning accepts the new plan, choose Resume separately to continue.

The conversation navigator updates while it is open. New child conversations can appear in your current search. If the selected conversation leaves the list, choose a new one before pressing Enter.

Ctrl+G then S selects a second conversation or closes the split. Side-by-side panes require at least 100 terminal columns. At a narrower width, the second conversation remains selected for the split; Ctrl+G then W switches the input pane. Widening the terminal restores both panes. Each pane keeps the message and position you were reading as the split opens, closes or changes width. Starting Gitjig again without an explicit target reopens the saved pair when both conversations are available. The last input conversation starts on the left. You can edit the draft while the terminal loads retained conversation history on startup, after switching conversations, or after opening a split. Archiving or deleting the input conversation in a split leaves the other pane open with its draft. Use your configured command key in place of Ctrl+G. The lifecycle menu (Ctrl+G then L) identifies archived conversations by name and full ID so you can restore the intended conversation even when names match.

`/name TEXT` saves an application display name. `/name` opens a text field; cancellation keeps the current name. `/name --reset` removes the explicit name and restores the derived label. Names contain 1..120 UTF-16 code units and no control characters. A governed conversation's actual role/purpose stays visible before its user label. Naming does not rename the native session file or change work, authority, history or pending obligations.

`/session` shows the current conversation's identity, display name, role, state, project, parent, native session identity and public model choice. Verified native history supplies message counts, recorded tokens and recorded cost, including after restart. Totals cover the whole native file, including abandoned branches, compaction/summary usage and copied fork context. They do not represent new conversation spend or billing. Missing or invalid usage is unavailable. Current context is unavailable without a live measurement; a live Pi session supplies its own context estimate. The command does not display credentials, private recipes or history paths. Escape closes it without clearing the command draft. The picker also shows bounded recent captured-input records and their separate handling/comparison states; see [Project file context](file-context.md).

`/fork` opens Pi's history tree. Use the arrow keys to select a context point, then press Enter to create and open a new conversation. Escape cancels and keeps the command draft. Browsing and selection leave the source history unchanged. The source must have verified native history. If its history or model changes while the selector is open, reopen the command.

`/clone` creates and opens a conversation with the current context and desired model choice. It also works for an empty conversation with no model selected. Each destination has its own draft and native identity. Forks and clones retain the original task references, shared allowances, delegation limits and pending governed obligations. Wait for active producers and cleanup to settle before copying their context. A successful command clears only its unchanged source command; newer and sibling drafts stay intact. If creation succeeds but opening fails, the diagnostic gives the new ID for `/resume`. Inspect that ID before manually repeating the creation command.

`/copy` copies the current branch's last assistant text, following Pi's text convention. It ignores thinking and tool arguments, trims surrounding whitespace and skips an empty aborted assistant message. If the latest remaining assistant message has no text, it reports unavailable rather than copying an older answer. Missing history, changed history scope, text over 1MiB or a failed clipboard write produces an error and keeps the command draft. This command uses the conversation where it was invoked, even if another view gains focus while history is read. Mouse selection copy remains separate.

These commands do not check out Git or create procedure standing. See [current capabilities and limits](capabilities.md). Generic positional prompts, stdin/print aliases, arbitrary plugins, prompt-template expansion and Pi RPC/JSONL compatibility are not provided; see [Usage](usage.md#noninteractive-input-limits).

Application conversations and assigned work use saved target model choices. A newly assigned child inherits the parent's desired choice; a target that already has a model keeps its own choice. Governed work captures that target choice as its baseline. Later default changes do not retarget that work or old execution records.

A waiting application conversation can resolve its saved model after restart. Automatic continuation requires complete dependency results and validated native history. Explicit resume can also account for unavailable dependency outcomes; an unavailable outcome is not success. Missing model, runtime, native history or cleanup leaves the waiting authorization available for repair. Work that used an explicit external profile requires its matching profile after restart. New owner input takes precedence over an older in-flight continuation.

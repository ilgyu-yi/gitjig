# User guide

These documents explain how to use gitjig to develop and manage your projects. They do not prescribe how contributors develop gitjig itself.

1. Read [Capabilities and limits](capabilities.md) before choosing a workflow.
2. Check [Requirements](requirements.md), then follow [Installation](installation.md) and [Startup setup](startup.md).
3. Use [Usage](usage.md) for project registration, accounts, conversations, managed changes and repository operations.
4. Use [Accounts and providers](providers.md) for authentication modes and provider restrictions.

| Task | Guide |
| --- | --- |
| Prepare an execution image from the installed recipe | [Execution image](runtime-image.md) |
| Inspect native repository requirements across hosting providers | [Repository inspection](repository-inspection.md) |
| Find retained local/GitHub branch integrations without recovery or send | [Branch integration records](integrations.md) |
| Inspect publication records, reconcile uncertainty and explicitly send prepared originals | [Publication records](publications.md) |
| Find retained GitHub issue/PR observations and prepare local summaries | [Repository contributions](repository-contributions.md) |
| Register repository targets, edit common settings and recover configuration in the terminal | [Repository configuration](repository-configuration.md) |
| Inspect local Git, edit conventions and prepare staged changes in CLI/TUI | [Local development](local-development.md) |
| Run a persistent objective and recover it | [Goals](goals.md) |
| Navigate, name, fork, clone or copy conversations | [Conversation commands](session-commands.md) |
| Configure keyboard controls | [Keybindings](keybindings.md) |
| Control steering and follow-up queues | [Queue preferences](session-preferences.md) |
| Submit project files and inspect captured inputs | [Project file context](file-context.md) |

Repository administrators and human developers can use local checks and repository guidance without agent planning or internal agent review transcripts. Feature availability and repository authority are separate; see each guide's prerequisites and limits.

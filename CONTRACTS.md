# Contracts

## C0. Status and interpretation

These are target product contracts, not claims of implemented support. Preconditions and outcomes below define observable acceptance. Each implementation must declare its supported environment and enforcement coverage. Design owns structure; this document owns behavioral conditions.

The normative subjects are gitjig's implementation and its managed procedure. For an adopting project's task, the actual owner requirements and applicable project rules define the requested feature behavior. Supplying these criteria does not add unrequested gitjig capabilities, installation behavior or whole-product acceptance features to that project. Mandatory agent conduct, independent judgments, verification, pending-finding accounting, execution restrictions and action eligibility still apply to the managed work. In particular, execution/tool/cleanup restrictions also apply to ordinary adopter tasks; they are not installer-only obligations. Work on gitjig itself remains subject to its relevant product implementation and acceptance requirements.

## C1. Task entry and resumption

**Basis:** D2, D7; P1, P3.

The agent entry declares discovered integrations and unsupported capabilities; missing optional local/repo assistance does not itself prevent agent work. Actual platform restrictions still apply. Starting a task establishes its canonical hosting target (host/repository/resource as applicable), intent, requirements, relevant policy, owner identity, explicit delegation, and expected endpoint. Delegation records allowed action classes and targets, endpoint, and any permitted repository-approval override; absent permission means not delegated. The author cannot widen this configuration. Retain the original owner instruction/source event and requirement content/version alongside its English interpretation. A mutable issue edit or agent summary cannot issue an authorized scope revision by itself. User changes are recorded and affected eligibility is re-evaluated. Operations declare their required repository objects and stage inputs. If a required PR/issue or other object does not yet exist, perform an authorized bootstrap or report a blocked prerequisite; do not invoke a consumer against a nonexistent object. Early draft publication satisfies its own action obligations and cannot be represented as reviewed completion. Missing information required for safe continuation produces a clarification state and names what is missing. Resuming compares retained evidence with current work and reports valid, stale, and unavailable obligations before continuing.

Initial governed admission commits its source, work, requirements, finite budgets, initial run, managed state and captured criteria together. A storage failure before that commit leaves no partial task or undiscoverable run. Failure during subsequent source capture retains the same discoverable work and its spent allowance for explicit recovery.

Every conversational producer receives the mandatory English working-language policy separately from its response-audience policy. Human-facing progress, clarification questions and final replies follow the explicit requested reply language or the substantive human conversation; Korean input receives Korean conversation unless the human requests another reply language. Generated goal/dependency messages, tool output and internal English work do not select a new human language. Reply language can be selected explicitly per conversation with /language using a language tag, or left automatic without a mandatory setup step. The selected default is stored with a revision in controller-owned conversation state and refreshed before every conversational model request, including tool loops and live follow-ups. Restart and compaction cannot replace this saved value. Explicit context clone/fork copies the preference; reparenting and unrelated conversations do not. Invalid saved values require visible repair rather than silent automatic fallback. Automatic mode interprets bounded initial and recent admitted human references instead of claiming a resolved language code; other panes, generated continuations and unadmitted input cannot supply them. A new explicit request may override an individual response; only the host setting changes the saved default. Assigned task results, role JSON and strict completion-review reports remain internal English. A human's direct input to an assigned conversation retains human-response guidance. Compaction produces English working summaries while preserving human reply-language preferences. Original input/evidence, literals, identifiers, schemas and intentional product localization are preserved. Runtime instructions enforce the language policy without rewriting outputs or treating a character-set heuristic as semantic verification.

New assigned dialogue runs retain the human native final separately from an English `conversation_report`. Bind that report to its actual native assistant tool call, successful tool result, last native input, original run/session/checkpoint and owner direction. Coordinator publication uses a v2 report-only projection and cannot substitute the human final for a missing report. Recheck direction and pending owner input synchronously after cleanup and inside result settlement; stale, failed, interrupted, unknown-cleanup or oversized reports cannot complete assignments. Historical v1 results retain their original meaning. Assigned history navigation, compaction and native user-bash maintenance cannot republish or replace the original task result, assignment state or dependencies.

Entry resolves governed-work identity from controller-owned origins and known artifact bindings rather than the caller's fresh-task label. A known continuation loads predecessor pending obligations and consumed resolution allowance before review or implementation proceeds. Missing or ambiguous required predecessor linkage reports unavailable continuation and names the needed origin/checkpoint; it cannot initialize an empty successful history. Changing task, session, or PR identifiers does not discharge findings or reset allowance. Authorized supersession/recovery records the changed scope or method, inherited obligation dispositions, and a bounded allowance decision within owner authorization. Existing authorization suffices; no extra confirmation is mandatory. Independent new work does not inherit unrelated obligations merely by sharing a repository.

## C2. Planning eligibility

**Basis:** D5; P8.

Before authoring implementation changes, an agent task has a recorded plan, independently produced challenge, and a decision addressing material alternatives or objections. The task's working representation is English even when conversation is not; consequential ambiguity requires clarification rather than invented intent. Material factual inputs include source or measurement provenance and scope; a partial census cannot be presented as exhaustive. The record identifies requirement sources versus provisional design choices and explains fit with all four documents at impact-proportionate depth, within their product implementation and managed-procedure scope (C0). Actual owner requirements and applicable project rules remain authoritative for the adopting task's requested feature behavior. It considers a simpler sufficient baseline, without requiring a fixed number of alternatives. A tiny edit may use a concise plan/challenge; it does not silently skip the obligation.

The controller identifies distinct author, challenger, and adjudication executions and their supplied inputs. An adjudicator cannot be the author or the producer of the disputed challenge. No model diversity or proven psychological independence is implied. Implementation is refused while required planning obligations are unresolved. An independent planning adjudicator may explicitly classify an upheld defect in the bound initial baseline as an implementation obligation, map its retained occurrence to the accepted requirements, and assign its remedy to that accepted plan. Every pending occurrence, including equivalent duplicates, needs explicit accounting. The original findings remain pending until verified repair and independent review; unresolved intent, source operands and objections to the plan still block implementation. An authorized requirement change records its source and reopens affected decisions.

After an explicit owner workflow-criteria refresh, the planning adjudicator's output schema and final parser share the exact captured refresh source and previous/current version tuple. A plan-accepting result with no explicit owner-decision request must include an independent criteria decision for that tuple. Rejected plans and explicit owner-decision requests may omit it; any supplied decision must still match the captured tuple. Preserve both `adopt` and `needs-owner` verdicts without selecting or inventing one. Missing required or mismatched decisions are unusable producer output, not completed adoption. The current host adoption check remains necessary: matching captured output cannot adopt a newer refresh. This contract adds no automatic correction turn, result-submission tool or execution allowance.

## C3. Verification evidence

Required checks produce runner-observed results tied to the retained effective candidate, requirement/fixture inputs and actual intended assertion, with observed duration and completion status. For material observable guarantees, healthy and requirement-derived adverse inputs reach the actual relevant consumer. A modified fixture invalidates prior evidence; a changed expected observation needs a demonstrated fixture defect or authorized requirement revision. A timeout or budget overrun is not a pass. Required coverage may change only through a recorded verification-plan decision consistent with the agreed requirements; the author cannot unilaterally dismiss a failure as irrelevant. A pass, failure, unavailable execution, and inactive enforcement remain distinct. Author assertions cannot substitute for required execution. Failed or unavailable required verification blocks the governed action and returns a recovery path.

A finite mixed verification plan accounts for each normalized requirement through one independently accepted strategy. Material behavioral guarantees retain actual healthy and adverse consumer cases. A before-first-edit baseline duty requires a separately identified execution of the immutable original base, with valid typed observations of the declared subject defect; a crash or arbitrary nonzero exit is not that evidence. Its receipt remains distinct from candidate success and cannot be created retrospectively after editing. An observable scope duty uses complete bound effective manifests and the actual scope predicate on both the current candidate and a host-derived forbidden delta. These host observations establish execution/comparison facts, not semantic scope approval. Required distinct reviewers and final adjudication bind exact strategy and witness identities to current premises. Missing, stale, foreign, partial or unavailable required evidence blocks action; author classification, a generic clear review or an unsupported qualitative strategy supplies no exemption. An independently accepted typed profile remains explicit across replanning and cleared selections; missing optional fields or a later unsupported capability cannot silently convert it into a genuine legacy plan. Existing original baseline evidence may be selected only under its qualified stable premises; unsupported historical remapping remains held rather than recreating a before-edit event. Until a typed carry composition is qualified, a repair repeats current checks/scope and distinct current review/adjudication, including a mechanical nit, within the remaining original allowance. Historical plans and failures retain their original meaning and spend.

## C4. Review and resolution

**Basis:** D5; P4, P8.

A review records its author/reviewer separation, exact candidate, assessed scope, findings, and outcome. The collector binds producer/role and actual input from the supervisor launch registry, not worker-supplied labels. Every required role/result in the action's declared roster must be complete and usable; a missing role cannot be inferred clear from the outputs that arrived. The reviewer confirms actual effective candidate content and baseline before assessing it. Independent runs use owned workspaces and per-run mutable scratch/environment; a reviewer cannot edit the author workspace or include pre-existing unrelated user edits. Before landing, reviewed local implementation must match the remote candidate; a test-only remote diff cannot inherit review of unpushed implementation. If a reviewer authors a remedy, a distinct execution independently verifies that remedy rather than the same resumed reviewer approving its own fix. Before consuming a new review or launching another panel, the controller processes any pending diagnosis/recovery requirement. A new clear result cannot reset an unresolved gate.

Every raw received finding occurrence is accounted for by a disposition or a link to an equivalent finding before resolution can be published. Producer and consumer agree on the meaning and required fields of review results through one owned definition or exercised boundary agreement. A pass label does not override nonempty findings. Incomplete transport or invalid output does not constitute a completed review. Invocation/transport/protocol failure is recorded separately from a semantic judgment, with safe diagnostics and bounded retry only for a supported transient condition. Select the current usable execution explicitly, preserve superseded/incomplete history, and carry unresolved findings forward; merely requiring exactly one record to exist is insufficient. Every blocking finding identifies an unmet requirement or invariant, supporting evidence, and a disposition: upheld, rejected, deferred by authorized scope change, or unresolved. Severity and mechanical repair eligibility are recorded separately. Unresolved validated blocking findings prevent completion and representative action eligibility. Required adjudication remains incomplete when a potentially blocking finding has unresolved validity or disposition, including when reproduction is unavailable; dependent action remains ineligible. Independently rejected findings and explicitly optional improvements remain nonblocking and do not silently become requirements. Disputes require an evidence-based disposition separate from the author's completion assertion. A reproduced material failure cannot be rejected by an unrelated passing test or an unexecuted assumption. Resolve it by rerunning its bound input on the repair, demonstrating and correcting a fixture/binding defect, or recording an authorized requirement revision. Grouped occurrences retain separate obligations unless actual evidence supports the shared remedy.

An exact mechanical remedy can retain a review's validity only after non-author authorization of its scope and controller/checker confirmation that the reviewed before-state and complete delta match it and relevant consumer checks preserve affected guarantees. Machine-consumed documents/configuration use their actual inventoried extractor/parser; unknown impact disables carry-forward and requires sufficient broader checking and affected review. This confirmation is a limited verification, not another open-ended review round. Uncertainty or extra changes require affected re-review. Carry-forward retains the original review and the remedy confirmation as a linked chain; it does not relabel the original reviewer as having reviewed an unseen revision.

A single adjudication function resolves disputes; uncertainty requires bounded measurement, a different method, or user decision rather than recursive reviewer hierarchies. No fixed reviewer count is universal. At governed-work entry a finite review-resolution budget is set; managed continuations consume that allowance rather than silently resetting it. An extension requires a recorded bounded recovery decision within owner authorization. When obligations are resolved and required evidence is current, review terminates successfully, including when the last permitted execution supplied that evidence. If required obligations remain, budget exhaustion, repeated no-progress findings, or unresolved conflicting judgments blocks and offers explicit replan, independent escalation, or user scope decision. None counts as approval. A scope decision cannot waive intrinsic agent-standing duties; withdrawing the work is always available. If old comparison operands are unavailable, recovery obtains them or explicitly re-establishes a current baseline and reruns affected verification/review, retaining all unresolved obligations. The blocked state names a runnable recovery and its re-entry conditions rather than trapping the task behind permanently stale evidence.

For an initial planning observation produced before a candidate existed, repair closure may use its exact retained baseline only through the independently validated carry bound to the current accepted plan and requirements. It requires changed effective candidate content, current required checks and fresh independent review. Invalid optional raw producer fields do not erase an interpretable claim or confer patch/reproduction authority; the original producer's validity is unchanged. Planning carry never establishes repaired status or completion.
